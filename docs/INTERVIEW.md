# FlowPilot 工程实现与面试讨论

项目实现自建采购门户的观察、填写、确认、恢复、提交和验证。真实模型接口已接入结构化规划代码，外部模型效果尚未验证。浏览器不使用个人真实登录状态，不进行外部采购。

## 三分钟演示

1. 输入“为研发部申请 3 台笔记本电脑，预算 18000 元，用于开发测试”，执行后检查页面字段、截图与差量事件。
2. 在等待确认状态刷新页面，从任务历史恢复，证明确认点已持久化；此时门户尚未有回执。
3. 点击确认，再查看新浏览器执行、回执和提交内容校验，下载报告。
4. 新建任务，在文字中加入 `DOM`，展示相同任务通过语义 DOM 完成。演示模式是规则规划，真实浏览器实际执行。

## 能解释的技术选择

| 问题 | 当前实现与取舍 |
| --- | --- |
| WebMCP 有什么新意？ | 页面把“准备申请”声明为结构化工具，与可见表单共享同一实现；浏览器支持时原生注册。它是实验 API，当前工作台通过本地页面工具适配器调用，并非完整 MCP 客户端。 |
| 为什么还要 DOM？ | 页面没有工具或工具填写不一致时，可通过标签与角色定位控件；语义定位比固定 CSS 路径更容易维护，但仍需要页面适配。 |
| 差量观察怎么做？ | 首次记录可见控件及工具目录，随后按标签比较控件结构和值，只存 changed / removed；不是完整 DOM diff 或视觉识别。 |
| 人工确认怎样防止偷换内容？ | 对规范化 payload 计算 SHA-256，确认接口校验摘要，提交前校验计划和页面字段，门户接口再校验 payload。 |
| 页面变了怎么办？ | 字段验证失败先回退 DOM 重填；无法满足枚举或标签时任务失败。当前不支持任意网站的自主布局修复。 |
| 确认后进程崩溃会重复提交吗？ | 回执表以 task_id 为主键，重试复用既有回执；状态和事件按检查点保存。不是对外部系统的通用 exactly-once 保证。 |
| 模型是否可以直接点提交？ | 模型只输出受约束的填写字段与路径。提交按钮调用位于 approved 分支，门户再次要求确认摘要匹配。 |
| 浏览器退出以后如何恢复？ | 不持有等待中的浏览器进程；保存字段、摘要、截图，恢复时新建浏览器并重放已确认字段。 |

## 代码入口

- `app/portal.html`：自建业务页面、实验性 WebMCP 注册、工具与表单共享逻辑。
- `app/browser.py`：页面观察、差量、页面工具 / 语义 DOM 填写和字段验证。
- `app/agent.py`：结构化计划、暂停确认与恢复提交流程。
- `app/main.py`：门户提交二次校验与幂等回执。
- `shared/api.py`：确认接口、任务状态、事件重放。
- `tests/`：确认摘要、重复提交、两种填写路径等回归测试。

## 使用边界

当前是本地单用户、自建门户应用，不是任意网页通用代理。只有临时浏览器，不具备个人登录态读取、OCR、视觉模型、外部网站通用操作、多租户鉴权或分布式任务队列。面试时将它们作为进一步设计问题讨论，不应写成已完成功能。

## 面试中的数字回答

完整申请字段一致：100/100；部门、物品、数量、预算、用途字段匹配：500/500。实际工具流程 12/12 通过。回答时同时说明“本地、合成用例、规则模式、无模型”；不要只说 100% 准确率。评测细节见 [评测记录](EVALUATION.md)。

规则路径保证可复现演示；模型路径用于把不同表达转为受约束计划。目前仅完成兼容接口与模拟响应分支测试，外部模型效果待测。
